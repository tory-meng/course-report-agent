# 测试与发布检查

本目录的自动测试使用随包合成案例、临时文件、假分词器和模拟服务响应。无需课程私有材料、模型权重、CUDA或正在运行的模型服务。测试并不把模拟响应当成真实模型效果。

## 1. 安装CPU测试依赖

在项目根目录运行，建议使用独立的Python 3.11环境：

```bash
python -m pip install -r requirements-docagent.txt -r requirements-structured.txt
```

其中`lm-format-enforcer==0.11.3`用于真正执行结构化解码核心的测试；不能因没有GPU而跳过这些测试。无需为这一步安装或启动基座模型。

## 2. 生成公开演示母版

发布包自带从零构建的演示母版与契约。重新生成时运行：

```bash
python scripts/build_demo_template.py
```

此母版只包含演示内容，不是原项目的学校课程报告，也不包含教师签名、原始成绩或原参考报告二进制。更换母版应连同契约和资产哈希一起更新，不能只替换DOCX文件。

## 3. 运行全部离线单元测试

```bash
python -B -m unittest discover -s tests -v
```

`-B`避免生成Python缓存；Windows和Linux均可使用此参数。测试结果应为`OK`；如有失败，保留完整回溯并修复，不通过删除用例、增加无条件skip或伪造测试数量来绕过。

主要覆盖范围：

- 原始成绩读取、姓名与学号绑定、课程身份冲突、缓考与缺项处理。
- 单项/总评、取整差异、课程目标及观测点的确定性计算。
- 缺少关键成绩时，在请求模型前停止。
- JSON Schema、真实LMFE约束核心、中文UTF-8分词边界及不完整JSON的拒绝。
- 输入Token预算、拆批、重试、同输入结果复用及失败记录保留。
- 来源引用、文件哈希、事实合并、参考内容与本课材料隔离。
- 教学目标关联、未来改进语气、图表名称与完整说明。
- 训练数据审核绑定、按课程分组隔离、标签掩码和禁止截断。
- 公开配置、发布文件筛选，以及模型/数据/凭据/本机路径的泄漏检查。

上游工作阶段的历史基线为325项自动测试。本实验包增加了公开分发和合成训练边界用例；当前数量以本次命令实际打印结果为准。

## 4. 运行不调用模型的报告冒烟验证

额外安装LibreOffice和中文字体后运行：

```bash
python run_report.py run \
  --case examples/demo_course/case.json \
  --runtime configs/runtime.example.json \
  --out outputs/demo_test_001 \
  --offline
```

每次使用新的输出目录。该命令仅使用合成成绩及固定演示内容，验证读取、计算、表图、Word/PDF链路；它不能证明真实模型已经学会资料识别或报告写作。

检查输出的`validation.json`、`run_manifest.json`、`calculations.json`和`pdf_validation.json`，并打开Word/PDF检查分页。真实课程验证还须独立核对原成绩、有效样本、公式及来源，不能只检查文档是否成功生成。

## 5. GPU训练与在线推理验证

参见[训练与微调](TRAINING.md)和[本地模型服务](LOCAL_INFERENCE.md)。这两类验证需要自行准备基座模型、合适显卡及有权使用的数据，因此不由CPU单元测试替代。

区分以下结果：

| 验证层级 | 能证明什么 |
| --- | --- |
| 离线单元测试 | 输入校验、业务计算、数据边界和可复现程序行为 |
| 合成报告冒烟 | 不依赖模型时的文档生成链路 |
| 合成训练smoke | 分词、梯度和Adapter保存链路；不代表领域效果 |
| 同输入基线/候选生成 | 实际模型在约定任务上的结构和内容差异 |
| 真实课程独立核验 | 已核对课程的来源、数值、表图及文稿质量 |

开发留出不是严格盲测。Loss降低、JSON可解析或约束通过率提高，均不能单独当作成绩识别准确率或整份报告质量提升。

## 6. 上传GitHub前检查

检查器不会上传文件，也不会执行`git add`、提交或推送。它只输出文件位置和规则名，不打印疑似密钥原文。

解压后的干净发布目录：

```bash
python -B scripts/check_release.py --mode all
```

已经运行实验的工作目录通常存在本地`outputs/`、模型或缓存；这些文件不应进入发布包。建立Git仓库并按`.gitignore`暂存准备上传的代码后，检查已跟踪文件：

```bash
git add .
python -B scripts/check_release.py --mode tracked
```

默认`--mode auto`在Git仓库有跟踪文件时检查跟踪文件；非Git目录或空索引目录检查全部文件。这样空Git索引不能被误报为检查通过。

检查内容包括：

- 默认每文件不超过5MiB，可用`--max-file-mib`显式修改上限。
- 不含模型权重、checkpoint、真实Excel/PDF资料或SQLite数据库。
- 除随包合成成绩`examples/demo_course/grades.csv`外，不含CSV、TSV或JSONL数据文件。
- `configs/`只允许`*.example.json`、公开模板注册表、材料入口配置及说明文件；即使强制暂存，本机活动配置也会被拒绝。课程`cases/`属于本地资源目录。
- 本地数据、模型、输入、输出及审核目录只保留说明和空目录占位。
- 不含Python缓存、嵌套压缩包、本地`.env`、外部符号链接或内嵌文档。
- 不含项目原机器路径及常见凭据格式。
- DOCX检查其XML成员，避免本机路径或嵌入资料躲在文档内部。

此检查是针对代码发布的启发式检查，不会判断任意姓名是否真实，也不证明素材发布授权；应只保留标记为合成的演示文件。README中列出的外部模型和私有课程材料均由运行者另行准备。
